Mini построена вокруг нескольких осознанных ограничений. Этот пост объясняет, какие они и почему важны.

## Ноль внешних запросов

Все ресурсы хостятся локально: шрифты, CSS, JavaScript, иконки. Читатели никогда не отправляют запросы к Google Fonts, CDN или сторонней аналитике по умолчанию. Это означает:

- **Быстрая загрузка** — нет DNS-запросов, нет водопада сторонних ресурсов
- **Полная приватность** — данные пользователей не утекают во внешние сервисы
- **Работает офлайн** — сайт работает без интернета после кеширования
- **GDPR-совместимость** — не нужны баннеры cookie для шрифтов или аналитики

Единственные исключения — опциональные: Mermaid (загружается с CDN постранично) и виджеты Telegram (если настроены).

## Условная загрузка

Тяжелые библиотеки никогда не загружаются глобально. Вместо этого они управляются флагами в front matter:

| Библиотека | Front matter | Размер |
|------------|-------------|--------|
| KaTeX | `math = true` | ~300 КБ |
| Mermaid | `mermaid = true` | ~2 МБ |
| Likely | всегда (если не отключен) | ~15 КБ |

Типичный пост загружает только HTML, CSS и один файл шрифта. Никакого JavaScript, если страница его не требует.

## Шрифт Inter

Mini использует [Inter](https://rsms.me/inter/) — шрифт, созданный специально для экранов. Включены только реально используемые начертания:

- **200** — легкие акценты интерфейса
- **300** — основной текст (комфортно для долгого чтения)
- **300 italic** — цитаты
- **400** — обычное начертание
- **500** — средний акцент
- **600** — жирный текст, заголовки
- **700** — усиленные заголовки

Файлы в формате WOFF2 с латиницей и кириллицей. Два начертания (300 и 600) предзагружаются в `<head>` для предотвращения сдвигов верстки.

## Render Hooks

Mini использует render hooks Hugo для улучшения вывода Markdown без шорткодов:

**Изображения** (`render-image.html`) — автоматически добавляют `loading="lazy"` и `decoding="async"` к каждому изображению. Никакого особого синтаксиса не нужно.

**Ссылки** (`render-link.html`) — определяют внешние URL и добавляют `target="_blank"` с `rel="noopener noreferrer"`. Внутренние ссылки остаются без изменений.

## Архитектура CSS

Все стили живут в двух partial-файлах:

- `style.html` — базовый сброс, типографика, сетка (не зависит от темы)
- `custom_head.html` — цвета, компоненты, темная тема, адаптивные правила

Нет этапа сборки, нет Sass, нет PostCSS. Чистый CSS в тегах `<style>`, встроенный в `<head>` для нулевой блокировки рендеринга. CSS-переменные делают кастомизацию простой:

```css
:root {
  --color-primary: #0060a0;
  --color-accent: #d04000;
}
```

## Реализация темной темы

Темная тема использует атрибут `data-theme` на `<html>`:

1. Инлайн-скрипт в `<head>` читает `localStorage` или `prefers-color-scheme` **до первой отрисовки** — никакой вспышки неправильной темы (FOUC)
2. CSS использует `[data-theme="dark"]` для всех темных переопределений
3. Переключатель в подвале сохраняет выбор в `localStorage`
4. Изменения системных настроек учитываются, пока пользователь явно не нажмет переключатель

## SEO

Каждая страница автоматически получает:

- Open Graph мета-теги (title, description, image, type)
- Структурированные данные (JSON-LD) для статей
- Канонические URL
- Hreflang-теги для мультиязычных страниц
- RSS-ленту с автообнаружением

## Кнопка копирования кода

Блоки кода показывают кнопку копирования при наведении — в правом верхнем углу, с анимацией галочки при успехе. Чистый JavaScript, без зависимостей. Кнопка наследует темный фон блока кода и выглядит нативно в обеих темах.

## Бюджет производительности

Типичная страница Mini весит менее 50 КБ (HTML + CSS + шрифты). Нет сдвигов верстки, нет накопительных прыжков контента. Оценки Lighthouse стабильно достигают 100/100 по Performance, Accessibility, Best Practices и SEO.
